# KDTIME 처음 보는 분을 위한 질문과 답

KDTIME(광덕고 시간표·성적·진학 상담 사이트)을 처음 맡거나 둘러보는 분이 자주 궁금해할 내용을 모았습니다.
앞부분은 **쓰는 사람**(선생님·관리자), 뒷부분은 **고치는 사람**(사이트 관리·개발)을 위한 내용입니다.

---

## A. 사이트 구성 (쓰는 사람)

**Q1. 이 사이트는 무엇을 하나요?**
학교 업무 몇 가지를 한곳에 모은 사이트입니다.
- 학생: 개인 시간표, 성적 리포트, 대입 결과(광덕고 사례)
- 선생님: 반·학년 성적 분석, 성적 산출, 최소성취수준(최성보), 진학 상담(관심 대학·NAVI·수시 지원 구성)
- 학년부: 비상연락망, 생기부 업무, 반편성 분리희망학생
- 관리자: 계정, 학사일정, 원본 자료 올리기, 백업

**Q2. 메뉴가 너무 많아요. 어디서부터 보면 되나요?**
- 학생 한 명을 보려면 위쪽에서 학생을 고르세요. 그 아래 "학생 작업 줄"(성적 리포트 · 개인 시간표 · 대입 결과 | 대학 탐색 · 관심대학·상담 · NAVI 분석)을 왼쪽부터 따라가면 됩니다.
- 내 업무(성적 산출, 공지, 학년부 일)는 **선생님 ZONE** 홈에 카드로 모여 있습니다. 마지막에 하던 일은 '이어서 하기'로 보입니다.
- 어디에 있는지 모르겠으면 명령 팔레트(검색 창)에서 메뉴 이름이나 학생 이름을 입력하세요.

**Q3. '기존 UI'와 '새 UI(다크·라이트)'는 무엇이 다른가요?**
같은 기능을 보여 주는 화면 모양만 다릅니다. 새 UI는 카드형 홈, 접히는 단계, 큰 글씨를 씁니다. 화면 위쪽에서 바꿀 수 있고, 고른 모드는 그 브라우저에 기억됩니다. 새 기능은 새 UI 기준으로 만듭니다.

**Q4. 계정 종류와 볼 수 있는 범위는요?**
| 계정 | 주로 하는 일 |
|---|---|
| 관리자 | 모든 화면, 계정·학사일정·원본 자료 관리, 백업 |
| 선생님(학급담임·학년부장·교과담임) | 담당 학년 성적·시간표, 성적 산출, 공지. 담임은 자기 반이 먼저 보임 |
| 부서 계정 | 정해진 학년의 자료 열람, 학년부 도구 |
| 학생 | 본인 시간표·성적·대입 결과 |

선생님마다 쓸 수 있는 기능(반별 성적, 학생 성적 비교, 모의고사 분석, 최성보)은 관리자가 계정별로 켜고 끕니다.

**Q5. 자료(성적·명단·시간표)는 어디서 들어오나요?**
관리자가 NEIS 등에서 받은 엑셀 파일을 관리자 화면에서 올립니다. 사이트가 파일을 읽어 정리한 뒤 학교 저장소에 넣습니다. 선생님이 성적 산출에서 올리는 지필·수행 파일은 그 과목 작업에만 쓰입니다.

**Q6. 잘못 올리거나 지웠어요. 되돌릴 수 있나요?**
자료를 덮어쓸 때 바로 전 내용이 자동 백업됩니다(같은 자료는 30분에 한 번). 최근 20개와 30일 동안 날마다 1개를 보관합니다. 관리자 화면의 '백업'에서 시점을 골라 되돌릴 수 있습니다.

**Q7. 업데이트 안내 팝업은 무엇인가요?**
새 버전을 배포하면 바뀐 내용을 2일 동안 팝업으로 한 번 보여 줍니다. '확인했어요'를 누르면 다시 뜨지 않습니다.

**Q8. '내 일정'에 적은 내용은 다른 사람이 보나요?**
다른 선생님 화면에는 나오지 않습니다. 다만 학교 저장소는 사이트 자체 로그인으로 보호하는 구조라 은행처럼 암호화된 비밀 공간은 아닙니다. 학생 이름·연락처 같은 민감한 개인정보는 일정 제목이나 메모에 적지 마세요.

**Q9. 일정 알림은 언제 오나요?**
- 마감 2일 전·1일 전: 사이트에 들어오면 팝업으로 알려 줍니다(하루 한 번).
- 당일: 화면 오른쪽 아래에 접을 수 있는 [오늘 할 일] 창이 뜹니다.
- '브라우저 알림 켜기'를 누르면 사이트를 열었을 때 브라우저 알림도 옵니다. 사이트를 닫아 둔 상태의 휴대폰 푸시는 아직 지원하지 않습니다. 휴대폰 달력으로 받고 싶으면 '캘린더 파일(.ics)'로 내보내 가져가세요.

**Q10. 화면이 하얗게 나오거나 "Error - Request ID"가 떠요.**
- 화면 전체가 "Error - Request ID: …"만 보이면 사이트를 올려 둔 Netlify 쪽 문제입니다. 보통 잠시 뒤 저절로 돌아옵니다. 오래 가면 Netlify 관리 화면에서 사용량·크레딧과 배포 상태를 확인하세요.
- 새 버전이 배포된 직후 화면 일부가 안 뜨면 사이트가 한 번 자동으로 새로고침합니다. 그래도 이상하면 강력 새로고침(Ctrl+Shift+R)을 해 보세요.

**Q11. 인쇄물이 화면과 다르게 나와요.**
인쇄는 화면을 그대로 찍지 않고 인쇄 전용 디자인(A4·B4)으로 다시 짭니다. 인쇄 버튼을 누르면 나오는 선택 창에서 용지와 넣을 항목을 고르세요. 브라우저 인쇄 창에서 '배경 그래픽'을 켜면 색 배지가 제대로 나옵니다.

## B. 사이트 설계 (고치는 사람)

**Q12. 어떤 기술로 만들었나요?**
- 화면: React + Vite (`src/`). 진입점은 `src/main.jsx`, 대부분의 화면 연결은 `src/App.jsx`입니다.
- 저장소: Firebase Firestore의 `kd_timetable_kv` 컬렉션 하나에 "키 → 값" 형태로 저장합니다(`src/storage.js`의 `readStorage` / `updateStorage`). 큰 값은 여러 문서로 나눠 저장합니다.
- 로그인 서버: Netlify Functions(`netlify/functions/*.mjs`, 주소 `/api/auth/*`). 비밀번호 암호화, 구글·카카오 간편 로그인을 처리합니다.
- 호스팅: Netlify. `main` 브랜치에 합쳐지면 자동으로 빌드·배포됩니다.

**Q13. 파일이 너무 커요. 어디부터 읽으면 되나요?**
| 파일 | 내용 |
|---|---|
| `App.jsx` | 로그인, 메뉴, 선생님 ZONE, 팝업 연결 |
| `Grades.jsx` | 학생 성적 리포트, 관심대학·상담, 상담 인쇄 |
| `SusiNaviBeta.jsx` | NAVI 분석, 수시 지원 구성 |
| `TeacherGradeAnalyzer.jsx` | 선생님 성적 산출 |
| `uiMode.js` | 새 UI 색 변수(`--kdn-*`)와 공통 스타일 |
| `*.js`(소문자 시작) | 화면 없는 계산 함수. 테스트가 붙어 있음 |

계산은 작은 `.js` 파일(예: `gradeEngine.js`, `teacherPlanner.js`, `classSeparation.js`)로 빼고, `tests/*.test.mjs`로 확인하는 것이 이 저장소의 규칙입니다.

**Q14. 새 기능을 넣는 순서는요?**
1. 계산·자료 정리는 `src/새기능.js`에 순수 함수로 만들고 `tests/새기능.test.mjs`를 씁니다.
2. 화면은 `src/새기능.jsx`에 만들고, 스타일은 컴포넌트 안 `<style>`에 `--kdn-*` 색 변수로 씁니다. 그래야 라이트·다크 둘 다 맞습니다.
3. `App.jsx`에서 메뉴나 선생님 ZONE에 연결합니다. 무거운 화면은 `lazy(() => import(...))`로 필요할 때만 불러옵니다.
4. `src/patchNotes.js` 맨 앞에 업데이트 안내를 한 건 추가합니다.
5. `npm test`와 `npm run build`가 통과하면 PR을 올립니다.

화면 규칙(버튼 강조색, 글자 크기, 인쇄)은 `docs/UI_GUIDE.md`를 따릅니다.

**Q15. 저장 키 이름은 어떻게 짓나요?**
`kd_기능_v버전:구분값` 형식을 씁니다. 예: `kd_class_separation_v1:2026:2:3`(연도·학년·반), `kd_teacher_planner_v1:teacher.아이디`. 형식을 크게 바꿀 때는 버전 숫자를 올리고, 옛 자료를 읽어 옮기는 코드를 함께 둡니다.

**Q16. 여러 사람이 동시에 저장하면 덮어쓰지 않나요?**
`updateStorage(키, 기본값, 바꾸는함수)`는 Firestore 트랜잭션으로 "지금 저장된 값"을 다시 읽어 바꿉니다. 그래서 두 사람이 동시에 다른 반을 저장해도 서로 지우지 않습니다. 단순히 통째로 쓰는 `writeStorage`는 덮어쓰므로 공용 자료에는 `updateStorage`를 쓰세요.

**Q17. 비밀번호나 API 키는 어디에 두나요?**
이 저장소는 **공개(public)** 입니다. 비밀 값은 절대 코드에 넣지 않습니다. 로그인 서버용 값(`FIREBASE_PRIVATE_KEY`, `SESSION_SECRET`, `KAKAO_*`)은 Netlify 관리 화면의 환경변수에 넣습니다. 빌드할 때 `scripts/write-function-env.mjs`가 서버 함수 묶음에만 넣고, 화면(dist)과 git에는 들어가지 않습니다. `/api/auth/status`에서 값이 '있음/없음'으로만 들어갔는지 확인할 수 있습니다.

**Q18. PR을 올렸는데 Netlify 미리보기가 '취소됨'이에요.**
의도한 설정입니다. 미리보기 빌드가 크레딧을 많이 써서 실제 배포가 멈춘 적이 있어, `netlify.toml`에서 PR·브랜치 미리보기를 끄고 `main` 배포만 빌드합니다. 확인은 `npm run dev`로 내 컴퓨터에서 하세요.

**Q19. 배포했는데 사용자 화면이 예전 그대로예요.**
사이트는 앱처럼 설치되는 PWA라 서비스 워커(`public/sw.js`)가 있습니다. 화면(HTML)은 항상 새로 받고, 빌드 파일만 기기에 보관하므로 보통 바로 바뀝니다. 그래도 그대로면 새로고침을 한 번 하거나 앱을 닫았다 여세요. `sw.js`의 `VERSION`을 올리면 보관 파일을 모두 새로 받습니다.

**Q20. 학생 개인정보를 다룰 때 지킬 점은요?**
- 테스트는 가짜 이름·학번으로 하고, 실제 학생 파일은 작업이 끝나면 지웁니다.
- 인쇄물·엑셀에는 개인정보가 들어가므로 화면에 '보관·폐기 주의' 안내를 붙입니다.
- 로그, 커밋 메시지, PR 설명에는 실제 학생 이름이나 연락처를 쓰지 않습니다.

**Q21. 테스트는 어떻게 돌리나요?**
`npm test`를 실행합니다(Node 내장 테스트, `tests/*.test.mjs`). 화면 모양은 테스트하지 않으니, 큰 화면 변경은 `npm run dev`로 띄워 데스크톱·휴대폰 폭(390px)에서 직접 확인합니다.
